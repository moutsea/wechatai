## 一、先说清楚能不能自动生成

| 做法 | 可行性 | 结论 |
| --- | --- | --- |
| 我直接截图 | ❌ | 需要的界面在**微信手机端**（我 → 设置 → 功能 → 插件）。本机只有桌面版微信，设置树不同、没有 ClawBot 插件分组；我也没有你的手机和微信账号。驱动你已登录的桌面微信需要辅助功能/录屏权限，且会把你的聊天列表拍进去。 |
| AI 生成「截图」 | ❌ | 生成模型写不对中文菜单文字，界面细节也会错；更要紧的是：把生成图当真实截图挂在教程里，等于告诉用户「你会看到这个界面」而实际不是 —— 用户照着找找不到，信任直接崩。 |
| 手写 SVG 界面示意图 | ⚠️ 部分 | 每个字可控、几 KB、不会过时（见 `design/image-assets/` 的 SVG 用法）。但示意图证明不了「你的界面长这样」，只适合讲**路径**，不适合讲**状态**（报错长什么样）。 |
| 你拍 + 我处理接入 | ✅ | 5 分钟能拍完。裁切、转码、写入代码、跑校验我来做。 |

**这 6 张必须是真截图**，三个理由：

1. **教程的可信度来自「所见即所得」。** 用户卡在「找不到插件入口」，只有真实界面能让他一眼确认自己走对了。
2. **现状有先例，且标注规范。** 现有 4 张产品截图都用 `caption` 标注「（演示界面）」「图中模型为演示数据」—— 真实截图 + 明确标注，这条规矩已经立好了。
3. **对 SEO 是实打实的收益。** 「ClawBot 不回复 / 找不到入口」这类词的 SERP 全是纯文字帖，带步骤截图的页面拿到的是点击和停留时长。

## 二、拍摄规格

- **设备**：你日常用的那台手机（界面主题、字号与用户一致，别用测试机）。
- **时机**：连接已建立的状态下拍；灰度未开放的账号优先补 A1（那种「没有入口」的状态本身就是排名素材）。
- **原始尺寸**：直接手机截图（iPhone 1170×2532 或更高）。**不用裁**，原图给我。
- **交付方式**：AirDrop / 微信文件传输到 Mac，把原图丢进 `public/images/docs/`（或先放桌面告诉我路径）。
- **隐私**：见第四节，先遮挡再给我。
- **我会做成**：宽 496 px、竖版、jpg，与现有 `ds-chat-settings.jpg`（496×953）等保持一致。

## 四、隐私遮挡清单（拍完先过一遍）

- [ ] 头像、昵称、微信号
- [ ] 聊天内容（B2 只保留系统提示那一行）
- [ ] 二维码（全部打码，不要只遮角）
- [ ] API Key（全遮，不要留前缀）
- [ ] 顶部状态栏里的手机号、运营商、电量以外的个人信息

打码用手机自带标记工具涂实心块即可，不要用高斯模糊（可能被还原）。

## 五、我拿到图之后做什么

1. 裁切掉无关区域，宽度统一 **496 px**，转 jpg（质量 82），落盘 `public/images/docs/`。
2. 按下面格式写进 `src/client/pages/guide-content.ts` 对应 section（`connect` / `reconnect`）的 `screenshots` 数组，`width/height` 填实际像素。需要跨文档复用的网页截图放到 `doc-screenshots.ts`：

```ts
screenshots: [{
  src: "/images/docs/wechat-settings-plugin.jpg",
  alt: "微信「设置」页面「功能」分组中的「插件」入口",
  caption: "「插件」在「设置」的「功能」分组里，不同微信版本位置略有差异。",
  width: 496,
  height: 764,
}],
```

3. 跑 `pnpm build` —— `scripts/verify-seo.mjs` 会断言 `/images/` 资源存在，缺图会直接 build 失败，所以不会出现上线后 404 的情况。
4. 顺带把 `/wechat-clawbot#entry`、`#no-reply` 两节也引用 A1、B2（这两节目前正缺图）。

## 六、如果你不想拍

两个退路，优劣明显：

- **A1/A2 退成 SVG 路径示意**：可用，几百字节，不会过时；但只解决「在哪」，不解决「长什么样」。B1–B3 不适合退。
- **暂不加图，改文案**：把「点哪里」写得更细（精确到分组标题和条目文字），比没有强，但 SERP 上仍然吃亏。

我的建议：至少拍 **A1 + B2** 两张（入口与报错，对应两个最值钱的查询），其余按你时间安排。
