## 代码证据与 A 项方案

- [DO 日统计](../src/server/admin-account.ts#L67) 和 [Go 日统计](../backend/internal/reporting/stats.go#L114) 都把已写入 `usage` 的请求计作成功。聊天、图片、远程 Agent 和云端任务的成功结算已追加带时间戳的记录。远程 Agent 包括 Grok 与 Muse，成功的主动任务沿用既有 `usage` 口径。复用同一事件口径与结算时间，按 Asia/Shanghai 切日，保持与 WM3 的 `requests > 0` 一致。失败、首次回复和 `last_reply_at` 均不参加计算。[DO 结算](../src/server/personal-account.ts#L4880) · [云端任务结算](../src/server/cloud-agent-settlement.ts#L54)
- [后台同步](../src/server/admin.ts#L75) 分页读取账号统计并覆盖 D1 快照，日统计只保留滚动 30 天。同步时间本身无法区分目标日无活跃、超出快照范围和源数据缺失。首选扩展现有管理员同步，为采集起点之后的注册队列，在目标日结束后从同一账号存储读取指定日的 `usage` 是否存在，并同时确认该日已完整覆盖。查询使用源端时间索引，按账号最多读取两个目标日。旧版响应缺字段、源读取失败、覆盖不足或同步未执行时，该账号的对应日仍待确认。
- D1 只需保存每个账号在 D1、D7 的已确认结果。采用现有 `admin_account_stats.data` 的独立 `retention` JSON 字段，按观察日保存至多两个结果及覆盖元数据。账号由现有 `user_id` 唯一键关联。有成功事件写活跃，完整覆盖且无成功事件写未活跃，字段缺失表示未知。修改 `saveAdminStats` 时在同一 SQL 写入中追加或合并留存事实及覆盖证据，并保留已有事实；常规快照刷新、赠送会员触发的同步、旧版响应和过期采样均需覆盖兼容测试。原始追加事件继续由账号 `usage` 保存，留存结果离开滚动 30 天窗口后仍保留。现有分页管理员同步负责刷新，API 读取仅查 D1 聚合。同步失败与原结算事务隔离。
- [账号路由](../src/server/account-route.ts#L83) 可走原 DO 或 Go，`usage` 在 [迁移清单](../backend/internal/legacy/personal-account-v1.json#L46) 中。按 `accountForAdmin` 选择当前账号的数据源。涉及已接管的 Go 账号、切换或回切时，需确认原事件时间和账本覆盖连续，再写入该日的确认结果。DO 的 `adminStats` 增加可选注册时间及完整采集起点参数，由来源计算最多两个目标日。Go 沿用现有无参数签名 RPC，Worker 包装层标记来源不可用，相关 HTTP 队列返回覆盖不足。当前路由与同步期间出现的路由切换均在 D1 检查，已观察到的来源不可用标记随快照保留。旧版响应缺字段时保留未知。仓库的部署说明记录了原 DO 业务写入状态，实际部署拓扑留待授权验收核对。当前代码可复用成功追加的账本和已有 JSON 存储。若实现验证推翻该前提，需给出具体失败路径及额外成本，再由用户决定存储或采集范围的变更。[Go 部署说明](../docs/go-backend-deployment.md#L3)

## B 项查询契约

- D0 取 `user.createdAt`，沿用 [后台对秒和毫秒的归一化](../src/server/admin.ts#L113)。D1 与 D7 分别检查 D0+1 和 D0+7 的自然日，范围为当日 00:00（含）至次日 00:00（不含）。D7 最早在 D0+8 的 00:00 成熟。两个指标独立判断。以新版本同步首次成功持久化新版留存采集元数据的时刻为采集开始依据，在同一 `retention` 字段保留首次采集时刻，后续同步继承该值；注册队列尚未成熟时也可仅记录该标记。该时刻取服务端实际成功采样及持久化时刻，固定在新版本采集能力生效之后。当前仍存在的账号记录中最早首次采集时刻的下一个上海自然日为完整注册日起点，首次同步当天整日排除。由此采用保守的前向起点，既有账本中的更早事件仅作为源资料。全部标记缺失时返回 `collection_not_started`。删除最早采集记录的账号可能使起点向后移动，响应须返回实际使用的 `collectionStartDay`。
- 分母是该日期队列中符合观察条件的注册账号数，包含确认未活跃的账号。分子是其中在目标日成功结算至少一次的去重账号数。首版按查询时仍存在的注册账号与现有账号删除规则计算，API 文档需写明注销会影响历史队列分母及采集起点。成熟且位于采集起点之后的整个注册日队列全部纳入覆盖检查，确认未活跃和未同步账号都属于应观察队列。任一应纳入账号缺少目标日覆盖，整队该周期返回 `available=false` 和原因。
- 查询约定 `GET /api/metrics/retention?days=30`，`days` 默认为 30，只接受 1–90 的整数。注册日窗口包含上海当天，返回明确的起止日期；当天及近期队列按各自观察窗判定。非法参数经专用鉴权后返回 400。响应含时区、生成时间、采集起点、注册日窗口和逐日的 `d1` / `d7`。各周期返回目标日、`available`、原因及分子分母和比率，比率使用 0–1 的数值。不可用时分子、分母和比率均为 null。固定原因区分 `collection_not_started`、`before_collection`、`window_incomplete`、`coverage_incomplete`、`empty_cohort`；采集与时间门槛按所列顺序判断；通过门槛后，空队列返回 `empty_cohort`，非空队列缺少任一覆盖返回 `coverage_incomplete`。分母非零且整队覆盖充分时，0% 才有意义。HTTP 响应和审计日志只含本接口所需的脱敏信息，省去账号 ID、邮箱、姓名、订单、微信标识和聊天内容。API 文档写明「历史不可回推」。
- WM1 已在 Session 中间件之前挂载 `/api/metrics` 与 `/api/metrics/*`，统一进入 `metricsRequest`。当前分发函数仅接受 health，留存需在鉴权和限流之后加入精确路径分发，并将固定路由名加入审计白名单。成功、参数错误、不可用和异常均经同一响应审计出口，已知路径非 GET 返回 405。复用现有 token、`API_LIMIT`、`no-store` 和匿名化审计，health 继续只读取元数据。相关实现见 [metricsRequest](../src/server/metrics.ts) 与 [路由挂载](../src/server/index.ts#L185)。普通 Session、Plus Session、管理员 Cookie 均不能替代凭据。未授权的读取返回 401。接口仅限读取留存汇总。

## 验收

1. **A 写入与覆盖。** 从成功调用走到持久化记录，同账号同日重复成功和重复同步都只计一次；失败不计。覆盖上海午夜边界、尚未同步、账号源查询失败、同步重试，以及账号切换时的覆盖判断。触发同步失败时，原调用与结算行为仍符合现有测试。覆盖首次采集标记持久化、首次同步当天排除、目标日超过 30 天仍能读取已确认结果、旧版无参数 RPC、旧版响应缺字段，以及赠送会员刷新不会覆盖留存事实。幂等与原子性用实际存储测试验证。
2. **B 人工可核对。** 同一注册日三个符合条件的账号，D1 仅 A 多次成功得到 1/3，D7 有 A、B 成功得到 2/3，已确认未活跃的 C 始终计入分母。仅修改 `last_reply_at`、首次回复或付款数据，结果一致。另用夹具覆盖上线前、上线日不完整、观察日结束前后、缺覆盖、空队列和确认的 0%。同时验证秒与毫秒注册时间得到同一天，以及账号删除后的分母与采集起点符合已声明口径。
3. **鉴权与输出。** 专用 Bearer 返回聚合或明确不可用，无 token 返回 401，错 token 与仅 Cookie 的管理员、普通用户及 Plus 请求均拒绝。检查响应和日志无个人明细或秘密，且查询不触发同步。对照现有后台与结算路径回归。补测全量回退旧写入再恢复时缺失记录返回不可用，以及 `days` 默认值与 1/90 边界、非法值 400、非 GET 405、限流 429、限流器或存储故障 503，以及 health 和前置指标路由。
4. **文档隔离与部署后验收。** 本评审文件仅存仓库根 `internal-docs/`，不登记为公开文档或运行时资源。功能验收时检查构建产物和 `/api/docs` 均不含本文。未来单独授权部署后，才用专用 token 核验聚合或不可用、无 token 401、D7 未成熟时明确不可用，验收记录不含凭据。
