# 网页设计优化与逐项审查

## 1. 工作台字号

- 根因：新手引导、插件和云端任务有独立的 12–13px 字号，未沿用全站字号。
- 实现：这些页面的操作说明使用正文、辅助信息使用小号字；共用字号改用 rem，根字号保留浏览器偏好，正文仍为 16px、宽屏 17px。命令和密钥区域也同步放大。
- 影响链路：全站字号变量 → 工作台引导、插件配置、任务与文件列表；未改变接口、会员权限或计费。
- 审查：检查字号继承、移动覆盖样式、命令区域及弹窗底部按钮；移除了遗漏的 11–12px 等宽字体声明。
- 验证：106 个相关客户端交互测试、typecheck、lint、构建及 SEO 检查通过。本地浏览器加载真实构建和内存 API，在 390px 下检查引导与插件页；引导正文 16px，页面及弹窗无横向溢出，底部操作可滚动到达。
- 限制：工作台使用模拟账号与 API，未验证生产账号、实际模型调用或支付；本项尚未部署。

## 2. 按用途简化新手引导

- 根因：用户未选择用途就需要阅读所有接入方式和费用；后续连接说明还会受其他已有插件影响。
- 实现：改为选择用途、准备服务、连接微信。按模型、已有 Agent、小薇、通知分别展示配置和费用；复用渠道、插件及 Plus 权限入口。切换步骤聚焦新标题，返回保留所选用途。
- 影响链路：新手引导 → 渠道配置 / 具体插件详情 → 微信连接；KimiSeek 导入继续使用原有流程，未新增购买或绕过权限的入口。
- 审查：修正选择 Agent 后仍提示配置普通模型的分支；小薇提示跟随服务状态，明确 Plus 和自备模型要求，不可用时入口为查看状态；通知保留回复通道和 Token 操作说明。保留已配置小薇的执行模型就绪反馈及所选 Agent 的快捷命令。
- 验证：新增 5 个客户端测试，连同概览、插件升级、云端助手及漏斗事件共 77 个测试通过；typecheck、lint、构建及 SEO 检查通过。补充审查时同步旧流程测试，并补齐点击用途直接进入准备步骤的事件，覆盖两种进入路径和所选插件命令。390px 本地浏览器实际切换用途，提示和焦点跟随选择，弹窗无横向溢出。
- 限制：服务端使用内存夹具；KimiSeek 真实关联、微信扫码及支付未联调，未部署。

## 3. 手机首页展示

- 根因：桌面示意图中的装饰标题、重复描述和大留白直接沿用到手机；渠道列表竖排占用较多高度。
- 实现：保留四张功能卡和三个配置 Tab，精简说明及移动示意图；渠道改为横向 Logo 与名称，窄屏两列，避免品牌名碎片化换行。
- 影响链路：首页功能展示 → 各 Agent 教程、模型接入教程、模型配置文档；保留独立跳转、费用和 Plus 条件。
- 审查：检查 320、390、1440px，修正最初三列横排导致英文名称换行过碎的问题；配置 Tab 切换、原有链接目的地及触屏按钮均保留。
- 验证：390px 首页约 9045px，较原预览减少约 529px；320px 约 9813px，减少约 836px。三种宽度无横向溢出。22 个相关客户端测试、67 项既有浏览器回归、typecheck、lint、构建及 SEO 检查通过；使用真实构建与本地内存 API 检查页面布局和切换。
- 限制：高度是本地预览测量，会随字体、设备和登录状态变化；未部署、未验收生产页面。

## 4. 手机套餐比较

- 根因：三张套餐卡各自完整重复六项权益，手机用户要滑过较长内容才看到年付入口。
- 实现：保留三张卡片；手机和平板卡片展示价格、按钮和三个主要额度，完整差异集中到免费版 / Plus 对比表。桌面仍在每张卡中列出权益。所有展示复用现有额度常量和同一份权益数据。
- 影响链路：套餐展示 → 注册 returnTo → 登录 → 所选周期卡片 → 原有 checkout；未修改订单接口、价格、权限或自动续费行为。
- 审查：核对年付折算、免费额度、月年权益一致性；对比表使用行列标题，窄屏无需横向滚动。更新了原先固定断言 22px 留白的测试，改为验证无 JavaScript 时的响应式权益展示。
- 验证：9 个套餐客户端测试和 8 项相关浏览器测试通过，覆盖显示价格对应订单、支付中禁用、错误归属、注册登录保留周期及无 JavaScript 展示；typecheck、lint、构建和 SEO 检查通过。390px 卡片约 363px，年付按钮约 1324px（原约 2011px）；320、390、1440px 及 320px 下 200% 根字号无横向溢出。
- 限制：支付使用模拟接口验证参数和跳转，没有创建真实付费订单；未部署、未做生产支付验收。

## 5. 长文档章节导航

- 根因：原本文目录仅位于正文开头，向下阅读后难以切换章节；桌面侧栏只有全站文章导航。
- 实现：桌面侧栏增加本文目录，手机提供右下角折叠目录。两者复用章节数据；手机选择后关闭菜单、聚焦目标章节，Escape 关闭并返回目录按钮。继续使用原生 details 与锚点，无需新依赖。
- 影响链路：文档章节数据 → 目录 → hash / 原有滚动定位 → 正文章节；保留全站文档搜索与导航、静态预渲染、React 接管时的展开和阅读状态。
- 审查：避免增加顶部常驻栏；菜单限制高度并可内部滚动，按钮至少 44px。将焦点放在真正的锚点章节上，避免原生锚点跳转覆盖标题焦点；页脚末尾留出手机按钮空间。
- 验证：54 项公共页面浏览器测试全通过，其中新增 4 项覆盖 320 / 390 / 1280px 的中途目录访问、章节焦点、Escape 和静态到 React 的菜单状态交接；typecheck、lint、构建与 SEO 检查通过。另检查 320px、200% 字号及短屏菜单，未横向溢出；关闭 JavaScript 后目录仍可展开并跳转。
- 限制：无 JavaScript 时选择目录后需手动收起；只验证了本地构建，未部署或在实体手机生产验收。

## 6. 手机页脚

- 根因：桌面的五组完整导航在手机上全部展开，页脚约 1523px，影响页面收尾和常用入口查找。
- 实现：手机常驻工作台、价格、入门教程、联系、隐私与 GitHub 六个入口，完整导航使用五组原生折叠列表；桌面保留原有多列展示。两种布局复用同一份链接数据，Markdown 下载仍使用普通链接。
- 影响链路：全站公共页脚 → 产品、文档、开发者、条款和开源仓库；共享组件同时用于首页、价格页和文档页，保留原有目的地。
- 审查：检查关闭分组的可访问性、44px 点击目标、桌面导航、链接类型，以及静态预渲染交接后的展开状态和焦点。桌面使用独立导航容器，避免强行显示关闭 details 中的内容导致语义错位。
- 验证：390px 页脚约 681px，320px 约 706px；320、390、1440px 无横向溢出，320px 下放大文字到 200% 仍可展开与阅读。无 JavaScript 时折叠导航可用，React 接管保留分组状态、焦点与滚动位置。
- 最终回归：全量客户端 259 个测试、浏览器 72 个测试、typecheck、lint、构建及 44 页预渲染 SEO 检查通过。同步补齐了第 2 项旧引导流程测试与不可用服务提示，相关修改归入第 2 项提交。
- 限制：使用本地构建和模拟 API；真实扫码、模型调用与支付未联调，未 push、未部署或生产验收。

## 发布前测试复核

- 根因：云端附件测试重建账户后，有三处未恢复手动闹钟控制，真实计时的微信轮询会混入附件请求计数；浏览器阅读位置断言也未容纳 1px 的布局取整。
- 修复：重建后的读取和手动唤醒都复用 `useManualAlarms`；阅读位置允许最多 1px 偏差，仍能检测跳回锚点等实际回归。仅调整测试，不改变生产调度、附件、计费或页面行为。
- 验证：云端入口整个文件的 107 项测试通过，保留任务重建、文件持久化、取消及请求次数断言；最终全量服务端 2144 项、客户端 259 项、浏览器 73 项测试通过，lint、typecheck、生产构建、44 页 SEO 检查和 Wrangler 部署预检通过。以上均为本地验证，实际发布与线上检查另行报告。
