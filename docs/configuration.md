## 服务端密钥

本地变量见 [`.dev.vars.example`](../.dev.vars.example)，真实值放 `.dev.vars`；生产使用 Cloudflare Secrets。不要给密钥加 `VITE_` 前缀，前端构建变量会公开。

| 配置                                        | 用途                                                |
| ------------------------------------------- | --------------------------------------------------- |
| `BETTER_AUTH_SECRET`                        | 登录会话与 OAuth 凭据加密                           |
| `ENCRYPTION_KEY`                            | 渠道密钥、连接凭据等加密；必须与登录密钥不同        |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | 可选 Google OAuth                                   |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | 可选 GitHub OAuth                                   |
| `STRIPE_*`                                  | 可选会员和 credits 支付，详见[支付文档](billing.md) |
| `KIMISEEK_CONNECT_SECRET`                   | 可选 KimiSeek 关联，须与对端共享配置一致            |
| `BILLING_NOTIFY_TOKEN`                      | 可选管理员付款通知；来自消息提醒插件                |
| `BILLING_NOTIFY_SCOPE`                      | `all`（默认）或 `first_payment`                     |

不要直接更换已有生产环境的加密密钥，否则旧凭据可能无法解密。迁移时同时保留数据库、文件和对应密钥备份。

## 公共运行参数

Wrangler 的 `vars` 管理非敏感参数：

| 配置                                        | 默认含义                                                  |
| ------------------------------------------- | --------------------------------------------------------- |
| `APP_URL`                                   | 当前站点源地址，用于登录、OAuth、支付和连接器             |
| `PUBLIC_SITE_URL`                           | 微信教程等公开链接的源地址；自部署改成自己的域名          |
| `FREE_DAILY_CREDITS` / `PLUS_DAILY_CREDITS` | 每日 100 / 1,000 credits                                  |
| `FREE_ASSISTANTS` / `PLUS_ASSISTANTS`       | 历史命名，实际为渠道上限 3 / 20                           |
| `FREE_SESSIONS` / `PLUS_SESSIONS`           | 会话上限 10 / 200                                         |
| `LLM_ALLOWED_HOSTS`                         | 可选上游域名限制，不能放 API Key                          |
| `KIMISEEK_URL` / `KIMISEEK_API_URL`         | 可选关联服务的网页与 API 地址                             |
| `AUTH_EMAIL_MODE`                           | 本地 `preview`，生产 `cloudflare`；生产不允许使用预览模式 |
| `AUTH_EMAIL_FROM`                           | 已启用 Cloudflare Email Sending 域名下的发件地址          |

Free 默认一条微信链接，Plus 最多十条。Free 最多配置 1 个插件，Plus 插件配置数量不限。会员到期保留最早创建的 1 个插件可用，其余配置保留但暂停；停用配置仍占名额。已绑定且凭据有效的超额微信链接继续收消息，只回复暂停原因与续费入口，不调用模型或 Agent、不扣 credits；收消息服务和云端回退采用相同规则。续费或删除旧链接释放名额后可恢复聊天，主动断开或凭据真正失效则停止接收。暂停配置仍可停用或修改别名，其余设置和调用受套餐限制。网页历史和附件处理等有 Plus 权益限制；具体规则由 `src/server` 校验，套餐文案和价格在 `src/shared/billing.ts`。自部署可以修改这些规则，不依赖微伴官方站点授权。改变套餐须同时更新服务端、网页、文档和测试；不要仅隐藏前端限制。

## AGT 服务端配置（接入准备）

当前代码包含客户端、回调认证与持久接收、任务存储、配置、账号开通、请求冻结、持久提交、任务对账、轮询停止、恢复运行器、终态结果准备、结算和终态投递基础模块。账号共享 alarm 已接入恢复运行器，可推进已持久保存任务的开通、提交恢复、对账、轮询、停止、结算及终态回复自动入队，并复用现有微信发送器；新任务接收、公开回调路由和用户入口仍未接入。设置 `CLOUD_AGENT_ENABLED=true` 不开放用户入口；已有持久任务符合执行条件时，运行器可自动开通账号并推进任务。账号开通模块先校验上游应用用户的应用、tenant 和账号归属，以及工作区的 tenant、名称和 restricted 隔离模式，再逐步保存映射和 profile 配置进度；校验失败不保存该步骤的资源 ID，也不进入下一步，修正配置或上游响应后可重试。已有映射会复用；应用、tenant 或服务地址变化时拒绝复用旧映射。下面的参数供服务端接入使用，模板保持关闭。

请求冻结模块按任务创建时保存的模型、profile 和回调配置生成完整请求，并加密保存；恢复时复用完全相同的请求正文，避免配置变化导致同一幂等键对应不同内容。停止、隐藏、超时、关闭开关或账号/会话/插件不再符合调用条件时不返回可提交正文；加密、解密后会重新检查。已经尝试提交却缺失原始请求时暂停提交，等待核对原任务，不重新生成。该模块本身不发送请求或结算 credits。冻结请求继续使用原回调密钥版本，轮换时仍须保留该版本，供未结束任务的回调验签使用。

持久提交模块在 POST 前保存尝试时间与结果待确认标记；执行资格仍有效时，重试使用同一正文和幂等键。响应须通过 tenant、工作区、会话与回调线索校验，且 Job 未被其他本地任务关联，才保存 Job 编号；提交响应中的结果不用于结算，后续仍由 GET 确认。首次尝试收到明确拒绝且无回调线索时，保存待通知的拒绝状态并释放执行占用；已有尝试、响应丢失或格式异常时保留待恢复状态。通用 HTTP 400 可能发生在上游创建 Job 之后，不能断言未接收；400、409 或关联校验冲突均转为只读对账，不再 POST。停止与清除意图不会被迟到响应覆盖。宿主负责准入、开通账号、失败退避和终态通知；账号运行器已通过共享 alarm 调用该模块推进持久任务；提交阶段不扣 credits，计费由终态结算模块完成。

首次提交前，若任务已有原始调用快照，会先校验输入 Token 与 credits 上限；确定超限或上限内无法返回正文时，在本地拒绝并释放执行占用，不发送 POST。已有提交尝试、待确认标记或回调线索时，不凭计量限制断言任务未提交，继续恢复原任务。

提交结果不明时的只读对账模块也已准备：先用 GET 核实已验签回调留下的任务线索；没有线索时每轮查询一页任务列表，保存游标和候选以供重启后继续。只有归属匹配且未被其他本地任务关联的唯一候选才会返回；列表须遍历完毕，有歧义或归属不符时保留待恢复状态，不根据正文或时间猜测。账号运行器已按任务待处理时间自动调用该模块；对账只查询原任务，不提交、取消或结算。

回调持久接收模块使用任务保存的密钥版本验签，再校验账号映射、应用、tenant、工作区与已关联的任务编号。新回调的去重记录与仍需查询上游的任务唤醒在同一事务内保存；相同回调重试可重复确认，标识相同但内容不同则拒绝。仅保存归属标识和正文摘要，不保存回调结果，也不根据回调确认提交、完成任务或扣 credits。关闭新提交不影响存量回调接收。后续公开路由仍须先校验路由 token、限制流式正文大小；接收成功后由宿主按任务的待处理时间安排共享 alarm，包括重复回调，以便调度失败后重试恢复。

已确认任务的轮询停止模块通过 GET 校验任务编号、tenant、工作区和会话归属，再保存终态结果供后续结算与交付；本身不判定成功计费。终态结果保存后直接复用，结算重试遵循宿主保存的 `nextAt`，原执行 deadline 和迟到回调不再提前唤醒该任务。停止意图先持久保存，再请求取消；取消响应不等于任务已结束，仍须等待 GET 确认。任务超时、调用资格变化或暂不支持的工具审批都会请求停止；每次外部请求后重读本地状态，隐藏任务不回填已清除的结果。存量任务查询不依赖开通 profile 或提交请求密钥，宿主须提供同一服务的有效凭据并负责 alarm 与失败退避。账号运行器已自动调度查询和取消，失败后按任务持久保存的退避时间继续恢复。

恢复运行器复用上述模块，每轮最多推进 6 个到期任务，每个任务只推进一次；任务之间检查时间预算，单次外部请求仍使用客户端超时。每个账号复用一个运行器实例；alarm 在运行前持久登记短期恢复唤醒，先推进云端任务，再进入微信长轮询，结束时将任务 `nextAt` 与其他后台工作合并安排下一次唤醒。构造器恢复已有任务的 alarm，保留更早的其他唤醒；微信没有可接收连接时也继续恢复和停止任务，活动任务的 Plus 到期时间单独参与调度。空闲消息轮询和二维码轮询的等待时间均受最近云端唤醒时间约束，到期后让出当前 alarm；避免空闲轮询拖后任务查询、执行截止检查或会员到期检查。模型调用和发送请求仍遵循各自预算，不由空闲轮询唤醒中断。停止且确定未提交的任务释放执行占用；提交结果不明时保留占用，停止、请求正文缺失或已有回调线索时只读对账，不重建请求。失败按任务持久保存退避时间，重启后继续；已有终态结果直接交给宿主完成结算与交付，不依赖上游配置或新提交开关。运行器通过宿主调用已有幂等结算与投递模块，不另建扣费或发送通道。宿主在提交前复核 Plus、余额、插件、原会话和连接代次；响应不明或已接单的任务不会因余额后来耗尽而停止恢复。仅切换当前会话不请求上游取消，最终写回和投递仍校验原归属。

终态结果准备模块 `prepareCloudAgentResult` 只读取轮询模块已校验并保存的终态结果。完整答案按原始调用快照的输入和平台截取后的输出计量，不使用上游 `usage` 或内部工具消耗；文本、计量数据和截取标记先持久冻结，结算重试和重启后复用，不重新计价。上游截断、拒答、补充信息、部分完成、失败或取消均返回不计费结果；补充问题与拒答说明一并保留，非成功正文最多保存 64,000 字符。平台按本次输出或 credits 上限截取成功答案时会明确提示；输入超限、credits 上限不足或上限内没有可用正文时，返回明确的不计费失败供宿主结束任务，不无限重试固定限制。提示建议缩短内容、缩小任务范围或联系运营方，不要求用户调整尚未提供的云端配置。缺失或不匹配的原始调用记录仍暂缓计量，不重建输入；存储等其他故障仍由运行器退避重试。隐藏任务不回填正文或计量快照；过期、停止或已离开原会话不阻断已有完整结果的计量准备，后续交付仍须遵守原会话归属。

结果准备本身不扣 credits、不将任务标为完成，也不写聊天记录或发送微信。结算模块 `settleCloudAgentTask` 复用结果准备，在 `await` 返回后重新读取终态、隐藏状态和原会话归属，再在同一同步事务内提交钱包扣费、平台计量、用量、结果缓存、有效会话的助手消息及消息数、任务终态和待交付状态。重复调用或重启后不会重复扣费或写入历史；任一步写入失败时整笔结算回滚，重试复用已冻结价格。账单中的插件 ID、版本与实例使用原始调用快照，不使用当前配置；调用归属不匹配时暂缓结算。完整答案在任务执行期间额度被其他请求用尽时，仍按冻结金额结算，欠额沿用钱包机制保存。

结算时已隐藏的任务不收费、不恢复清除内容；失败、取消或其他不计费结果结束执行占用并保留待通知状态。已离开原会话但未清除的完整结果照常结算，仅保存在任务与结果缓存中，不追加聊天记录或安排通知。有效会话成功落历史时同步更新消息数和时间，保留用户标题。宿主须同步校验当前连接、插件和会话选择是否仍属于原任务，并负责共享 alarm；结算使用任务表中的终态与 `delivered=0` 作为持久待交付记录，不写微信 inbox 或发送消息。账号运行器已复用此结算模块，并在同轮将有效终态回复交给投递模块入队；失败重试和重启后继续使用原任务编号，避免重复扣费。用户任务入口尚未开放。

终态投递模块 `CloudAgentDelivery` 将结果说明与正文一次性写入现有微信 inbox，使用固定的 `cloud:<任务编号>` 标识，并与任务的入队标记在同一事务保存。`sync` 重试只核对状态，不改正文、分段游标或账单；已入队记录丢失、被清除或已标为失败时不重新生成，也不凭 inbox 的 `done` 状态推断送达。现有发送器在每段发送前及外部请求后检查原会话、插件、连接和绑定代次；原会话归属已改变时丢弃剩余队列，迟到响应不推进旧游标。网络请求前已发出的内容无法撤回。最后一段确认成功后，inbox 完成与任务 `deliveryStatus=sent` 在同一事务保存。成功答案只有完整送达后才计入微信回复统计；失败、取消通知不计成功答案。

云端结果连续发送失败 5 次后进入 `waiting_context`；缺少 context 时立即等待。队列保留原正文、发送 ID 和未确认分段的位置，任务仍为待投递，不改执行状态、结果或已结算金额。连接提示结果已保留，请用户在微信发送 `/wx help` 恢复接收，无需重新提交任务；该命令由微伴处理，不调用模型或 Agent，也不消耗 credits。普通文字消息仍按当前会话处理，可能创建新任务并另行计费。空轮询或不含 context 的消息不会清除等待提示。恢复接收提示以该微信链接仍在等待 context 的云端回复为准；取消或作废最后一条待发回复后立即消失，其他会话仍有等待结果时保留，真实连接故障优先显示。原微信收到含 context 的新消息后唤醒队列，重新校验原会话归属并续传未确认部分，不重新执行或扣费；重启后保留相同恢复状态。发送请求期间已有新 context 到达时直接使用新 context 重试，避免错过唤醒。微信登录过期仍提示重新扫码。

投递检查与结算共用原会话匹配规则；宿主仍须提供当前插件、连接和会话选择的同步归属校验。清空或删除会话、清除全部历史，以及删除模型或渠道时，同步清除相关任务在微伴保存的输入、结果、冻结请求和结果快照，并清理结果缓存及待发送正文；已离开原会话的结果缓存也按任务编号清理。任务隐藏后，迟到结果不会恢复正文或产生新扣费；账单、平台计量记录和已结算金额保留，未结束任务登记停止意图。重置上下文或归档会话时，登记停止意图并作废相关任务的自动投递资格，清理待发正文；输入、请求、已保存结果和账单保留，恢复会话也不重发旧结果。解绑、删除微信连接，或通过校验后开始重新绑定时，对该连接的任务作相同停止及投递作废处理，不影响其他连接；二维码获取失败也不恢复旧任务，绑定前校验失败则保留原连接和任务。停止意图不等于上游已停止，取消前完成的有效结果仍按原规则结算，但不写回会话或自动发送。切换会话仍保留历史，不按清除处理。网页重置或清理会话、清除全部历史，以及删除模型或渠道后，主动提前已有 alarm，并中断正在等待的空闲消息或二维码轮询，使当前轮及时退出，不等待原轮询或重试间隔。账号运行器通过共享 alarm 推进已登记的上游停止，并调用 `sync` 安排有效终态回复。没有持久任务时不发起 AGT 请求，也不创建云端通知。

停用或删除插件时，按插件实例登记 AGT 任务停止意图，并同步作废自动投递和清理待发正文；快捷停用与完整配置保存采用相同规则。重新启用插件也不补发旧任务结果，其他插件不受影响。删除模型或渠道连带移除插件时同样处理，包括该插件在其他模型会话中的任务；原会话未被清除时，任务输入、已保存结果和账单保留，迟到的有效结果仍按原规则结算，但不写回会话或自动发送。仅修改已启用插件的别名或配置校验失败时，不触发这项停止处理。这些钩子持久保存停止意图，由后续 alarm 查询上游状态并请求取消；最终停止仍以上游终态为准。

停止原因独立保存在任务 `stopReason`，兼容旧任务仅在 `error` 保存原因的记录。生命周期钩子登记停止时，会区分此前的对账进度与停止原因；运行器或轮询模块补齐缺失原因，已有原因不会被后来的故障、审批或配置变化覆盖。GET 期间发生的停止也会在保存终态前补齐原因。取消或失败通知保留原因及处理建议，将“正在请求停止”更新为终态表述；清除记录时同步清除该原因。

新任务准入解析器 `cloudAgentConfig` 校验完整运营配置；恢复运行器使用 `cloudAgentConnectionConfig`，只读取当前服务地址、应用、tenant 和凭据，再搭配任务已保存的模型、profile 和工作区名称。当前新任务模型缺失、profile 或工作区前缀无效，不阻断已有任务的开通重试、原请求重试、只读对账、查询和取消；服务地址、应用或 tenant 变化仍暂停恢复，凭据缺失也不会发请求。提交前停止的通知保留具体原因和处理建议，补充“任务未提交，未扣 credits”；通知失败重试不会丢失原因。生命周期钩子已写入停止标记但缺少原因时，运行器从宿主补齐原因；补齐本身不改变重试时间或次数，也不覆盖已有原因。清除的任务不再通知。

非敏感参数配置在对应环境的 Wrangler `vars`，生产配置写入被忽略的 `wrangler.production.local.jsonc` 的 `env.production.vars`。本地与生产应使用不同的 AGT 应用、凭据和工作区前缀；修改模板后运行 `pnpm cf-typegen`。

| 参数                           | 说明                                                                                                                                                                 |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLOUD_AGENT_ENABLED`          | 默认 `false`；仅 `true` / `1`（不区分大小写）允许新任务准入与提交。关闭时须保留原服务地址、应用、tenant 和有效凭据，供存量任务查询、对账和取消使用                   |
| `AGT_ORIGIN`                   | 固定 HTTPS origin，不带 API 路径、用户名、查询参数或 fragment；允许尾部 `/`。仅回环地址允许 HTTP                                                                     |

| `AGT_MODEL`                    | 新任务必填的上游模型 ID；已有任务使用保存的模型。本地配置解析不验证模型是否已开放或账户是否有权限                                                                    |

回调密钥轮换时，先在 `AGT_CALLBACK_KEYS` 中保留旧版本、加入新版本，再更新 `AGT_CALLBACK_KEY_VERSION`，并在旧任务及回调有效期结束前保留旧值。未配置密钥环的 `v1` 使用既有 `ENCRYPTION_KEY` 作为主密钥；如从此默认状态迁移到显式密钥环，需要将原 `ENCRYPTION_KEY` 的同一个值保留为 `v1`，把独立新密钥放到 `v2` 后切换新任务。显式密钥环不再为缺失版本回退；不能用新的随机值覆盖仍有在途任务的 `v1`，也不要为此更换 `ENCRYPTION_KEY`。

## OAuth

创建自己的 Google Web OAuth 客户端、GitHub OAuth App。回调地址分别为：

```text
https://你的域名/api/auth/callback/google
https://你的域名/api/auth/callback/github
```

本地用 `http://localhost:5173` 替换源地址。Google 的 Authorized JavaScript origins 填源地址。没有完整配置的平台保持不可用。同邮箱账户关联保留 Better Auth 的邮箱验证检查，不根据未经验证的邮箱自动合并身份。

## 邮箱注册与找回密码

邮箱注册要求 10–128 个字符的密码，网页再次输入确认。注册后发送验证邮件，未验证不能使用邮箱密码登录；验证链接 1 小时内有效，首次成功验证后建立登录会话。Google / GitHub 保留各自返回的邮箱验证状态，不把普通注册账号自动标为已验证。

已有未验证账号重复注册或重发验证邮件时，改为发送「确认邮箱并设置密码」邮件，由邮箱主人重新设置密码。此时原验证链接不能再激活原密码，注册请求本身也不会覆盖密码。已验证账号重复注册会收到登录指引，密码不变；接口仍返回通用结果。

登录页提供「忘记密码」。重置链接 30 分钟内有效，成功使用后失效；重置密码同时验证邮箱归属、撤销该账号的旧登录会话和所有未使用的重置链接。这些变更在同一个 D1 事务中完成，并发提交不同重置链接也只有一次成功。已经登录的旧账号不会因本次升级被强制退出；未验证的旧账号下次使用邮箱密码登录时，需要先完成验证。

发信使用 Workers 的 `AUTH_EMAIL` 原生绑定，无需在应用中配置邮件 API Token。生产须在 `env.production` 中配置：

```jsonc
"send_email": [{ "name": "AUTH_EMAIL", "allowed_sender_addresses": ["noreply@mail.example.com"] }],
"vars": {
  "AUTH_EMAIL_MODE": "cloudflare",
  "AUTH_EMAIL_FROM": "noreply@mail.example.com"
}
```

先在 Cloudflare Email Service 开通自己的发信域名并确认 SPF、DKIM、DMARC 已生效，再启用邮箱注册。只创建绑定或填写发件地址不能完成域名验证。缺少发信配置时，注册和发送邮件接口返回 503，不会跳过验证。

本地默认 `preview`：不向真实邮箱发送邮件，服务终端输出 `auth.email.preview`，其中 `url` 是可在本地打开的验证或重置链接。只有 `APP_URL` 为回环地址才允许此模式；不要将本地开发端口公开到互联网。测试捕获邮件内容而不实际发信。

注册、重发验证邮件和找回密码共用服务端限额：同一邮箱每 60 秒一次、每小时 5 次、每天 20 次，另有按 IP 的认证请求限制。D1 保存邮箱哈希和计数，后台清理两天前的限额记录。邮件发送通过 `waitUntil` 完成，失败记录为 `auth.email.delivery_failed`，日志不包含地址、密码或链接；用户可稍后重发。未知邮箱和已有邮箱返回通用提示，避免暴露账号是否存在。

这三个发信接口仅接受 `Content-Type: application/json`（可带 charset 参数）；表单或其他格式返回 415，避免不同解析方式绕过邮箱限额。此限制不适用于第三方登录回调。

## 模型与搜索

模型 API Key 由用户在网页配置，不是全站环境变量。普通 LLM 支持三种协议；输入根地址后自动补全相应接口路径。渠道与模型分层，模型维护独立提示词、上下文窗口及输入输出上限。

添加渠道时可直接选择 DeepSeek、Kimi、智谱、通义千问（百炼）、火山方舟、MiniMax、硅基流动、OpenAI、Claude、Gemini、OpenRouter 或 xAI，再填写自己的 API Key。协议、服务地址和渠道名称由预设填入；名称与备注可在「更多设置」中修改。「自定义」保留三种协议和 Base URL 的完整配置能力，KimiSeek 一键关联入口也继续保留。

智谱、百炼和火山方舟的 Coding Plan 使用独立预设，失败时不会切换到按量付费接口。套餐可能限定接入工具和使用场景，选用前请查看服务商说明；预设地址不代表套餐授权微伴接入。百炼默认北京地域，其他地域或专属空间地址使用自定义配置。预设及官方说明链接集中维护在 `src/shared/channel-providers.ts`。

新建预设渠道后会自动获取可用模型，并按文本、生图与其他模型归类；审核、实时音频、转写等非聊天模型不会成为默认聊天模型。获取失败不影响渠道保存，可稍后重试或手动填写模型 ID。新导入文本模型的输出上限取平台默认值、上游声明的输出上限与上下文窗口一半中的最小值；重复导入不覆盖用户已保存的模型设置。

xAI 的 Grok Imagine 和 Gemini Flash / Pro Image 生图系列归入生图分类，兼容 `models/` 和服务商前缀。对于已确认的官方协议限制，导入时会跳过不兼容模型并显示数量：例如 OpenAI 官方的 `gpt-audio` / `gpt-4o-audio-preview` 系列只能在 Chat Completions 渠道中使用，不能在 Responses 渠道激活；官方明确标为 Responses 专用的模型（如 `o3-pro`）在切换到 Chat Completions 后也不能激活。已确认的 Responses 专属模型维护在 `src/shared/model-compatibility.ts`，不通过笼统的 `pro` / `codex` 名称猜测协议。已有配置和记录保留，页面显示切换协议的提示；新会话、插件选模、微信连接校验和实际请求都会检查兼容性。此限制按官方域名匹配，不根据相同模型名称限制第三方渠道；未知模型仍以实际服务商能力为准。

编辑已有渠道不会自动导入模型或改写原地址。同一 API 根路径下切换协议可复用已保存的 Key；更换域名、网关前缀或 Coding Plan 入口时，要求重新填写 Key，避免把旧密钥带到另一家服务商或套餐。

渠道编辑器会实时显示所选协议的**实际请求地址**，可在保存前与服务商文档核对。地址拼接遵循以下规则：

- 保留 `/v1`、`/v4`、`/v1beta` 等已有版本前缀。例如智谱 Coding Plan 的 `https://open.bigmodel.cn/api/coding/paas/v4` 使用 **OpenAI Chat Completions** 协议，最终请求 `/api/coding/paas/v4/chat/completions`。[智谱文档](https://docs.bigmodel.cn/cn/coding-plan/quick-start)
- [Gemini OpenAI 兼容接口](https://ai.google.dev/gemini-api/docs/openai)的 `/v1beta/openai` 和 [Cloudflare OpenAI 网关](https://developers.cloudflare.com/ai-gateway/usage/providers/openai/)的 `/v1/{account_id}/{gateway_id}/openai` 直接补全 `/chat/completions` 等资源路径，不额外添加 `/v1`。Cloudflare 的 Anthropic 网关仍补全 `/v1/messages`。
- 粘贴以 `/chat/completions`、`/responses`、`/messages`、`/models` 或 `/images/generations` 结尾的完整地址时，保留其根路径；切换协议时只更换接口后缀。未知服务商也可通过这种方式明确指定路径。
- 其他未包含版本的根地址仍默认补全 `/v1`，保留原有网关前缀。不会自动换域名、切换计费入口或尝试其他地址。

不同协议可能使用不同的 Base URL；预览只展示请求路径，不代表上游支持对应协议或模型。服务商未开放模型列表接口时，可手动添加模型 ID。

DS Chat 需要用户自行提供搜索 API；AI 生图也使用用户自己的上游。OpenClaw / Hermes 在用户自己的设备或服务器运行，微伴只承担消息传输和结果交付。

## 品牌与自部署域名

当前公开页面保留微伴品牌。换域名部署时，除 Wrangler 参数外，还需调整：

- `src/shared/seo.ts`：`SITE_URL`、站点名称和分享图。
- `src/shared/site-info.ts`：联系邮箱、政策更新时间；同步检查条款与隐私正文。
- `scripts/verify-seo.mjs` 与相关测试：校验目标域名和联系信息。
- `public/robots.txt`、`scripts/prerender.mjs` 生成的 sitemap 以及文档中的绝对链接。

公开页面在构建时预渲染，修改后重新执行 `pnpm build`。第三方图标只用于识别服务，不代表官方合作；更换产品品牌时请一并检查素材说明。

## KimiSeek（可选）

基础模型渠道无需 KimiSeek。一键关联需要同时控制 KimiSeek 服务端，部署其配套签名接口并配置相同的共享密钥。没有这一条件时不要开启；只填公开的 KimiSeek API Key 不能启用账户一键关联。跨服务凭据不接受浏览器提供的用户身份作为可信依据。
