# 云端 Agent 部署说明

[返回 README](../README.md) · [用户使用指南](https://wechatai.app/docs/cloud-agent)

云端 Agent 是可选的 Plus 插件，默认关闭。运营方提供 AGT 服务与托管模型，用户无需自备 API Key；不是 OpenClaw / Hermes 的云托管。当前仅支持文字、微信已转写的语音，以及账号工作空间内的记忆搜索和保存，不开放浏览器、执行沙箱、人工审批或自主定时任务。

## 配置与启用

非敏感参数放在相应环境的 Wrangler `vars` 中；生产环境由私有配置覆盖时，以实际部署配置为准。`AGT_APP_KEY`、`AGT_CALLBACK_KEYS` 使用 Cloudflare Secrets，本地可放在被忽略的 `.dev.vars` 中。不要把运营方 Key 发给浏览器或用户。

| 配置                           | 用途与默认值                                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `CLOUD_AGENT_ENABLED`          | 默认 `false`，配置完成、联调通过后才设为 `true`                                                                      |
| `AGT_ORIGIN`                   | AGT 服务的 HTTPS origin，无路径、查询或凭据；本地 loopback 允许 HTTP                                                 |
| `AGT_APP_ID`、`AGT_TENANT_ID`  | 运营方的应用与 tenant 标识                                                                                           |
| `AGT_APP_KEY`                  | 应用凭据，需有开通应用用户、管理受限工作空间及成员、配置 Agent 与工具、执行和查询任务的权限                          |
| `AGT_MODEL`                    | 运营方托管模型标识，必填                                                                                             |
| `AGT_AGENT_ID`                 | profile 名称前缀，默认 `wechatai`，实际追加 `-v1`；小写字母开头，仅含小写字母、数字、`.`、`_`、`-`，前缀最多 61 字符 |
| `AGT_WORKSPACE_PREFIX`         | 默认 `wechatai`，模板按本地/生产区分；仅含英文字母、数字、`_`、`-`，最多 87 字符                                     |
| `CLOUD_AGENT_DAILY_LIMIT`      | 每账号每日受理次数，默认 30，范围 1–1000，小数向下取整                                                               |
| `CLOUD_AGENT_DEADLINE_MINUTES` | 默认 10 分钟，范围 1–30；到时请求停止，仍需上游确认                                                                  |
| `AGT_CALLBACK_KEY_VERSION`     | 新任务回调密钥版本，默认 `v1`，1–32 位英文字母、数字、`_`、`-`                                                       |
| `AGT_CALLBACK_KEYS`            | 版本到密钥的 JSON 对象，如 `{"v1":"<至少 32 字符的随机密钥>"}`；轮换见下文                                           |
| `PUBLIC_SITE_URL`              | 当前部署的公开 HTTPS 域名，用于生成 AGT 回调地址                                                                     |

数值限额会约束到上述范围；负数或非法值回退默认值。每账号最多 1 个活动任务，包含尚未确认上游是否受理的任务，不能通过重复发送绕过。

开关开启且配置完整后，插件页才允许 Plus 用户添加、启用云端 Agent。无需本地渠道或文本模型即可扫码连接。配置显示可用仅代表本地检查通过，不代表 AGT 网络、权限或模型已联调成功；账号和工作空间在首次任务时按需开通。

## 隔离、模型与回调密钥变更

每账号映射独立的应用用户与 restricted 工作空间，同账号云端会话可能共享记忆。应用、tenant 或服务地址改变后，旧映射不会自动迁移；不要直接用新的服务替换仍有任务的旧服务。

模型、profile、工作空间名称和完整请求在任务创建或首次提交前冻结。重试复用原请求，不随当前默认配置变化。更换模型时同时更换 `AGT_AGENT_ID` 前缀，避免覆盖仍供旧任务使用的 profile；旧任务恢复仍使用保存的模型与 profile。

回调路径为 `/api/integrations/agt/callback/:token`，完整 URL 与每任务凭据由微伴自动生成，需要 AGT 可访问 `PUBLIC_SITE_URL`。回调仅唤醒任务对账，不能凭回调正文扣费；结果以服务端查询 AGT 后的权威终态为准，缺失回调时由轮询恢复。

未配置 `AGT_CALLBACK_KEYS` 时，仅 `v1` 使用既有 `ENCRYPTION_KEY` 派生每任务密钥。迁移到显式密钥环时，把原 `ENCRYPTION_KEY` 的同一个值保留为 `v1`，将新的随机密钥放入 `v2`，再将 `AGT_CALLBACK_KEY_VERSION` 切到 `v2`。所有旧任务及其回调处理完成前保留旧版本；显式密钥环不会为缺失版本回退，也不能用新随机值覆盖仍在使用的 `v1`。不要为轮换回调密钥而更换用于存储加密的 `ENCRYPTION_KEY`。

## 任务、费用与停用

微信通过 `/use 快捷名` 默认进入，或 `@快捷名 内容` 单次调用。添加、启用插件和扫码不改变默认 AI；网页可显式创建并选择云会话，本身不提交任务或扣费。实际任务在同一同步事务中校验 Plus、余额、并发、当日次数，并写入任务与宿主消息；重复源消息复用原任务。

接收任务时先预占一次当日次数；确定未提交或被上游明确拒绝提交时，任务进入 `rejected` 并释放预占次数。上游已受理后的失败或取消仍计次；请求停止本身不会立即释放次数，提交结果不明时继续保留预占，直到确认原任务。提交前校验被拒绝的消息不占次数。

模型成本由运营方承担；用户按平台输入与最终输出结算 credits，不计内部模型与工具消耗，不预扣，成功后可能形成负余额。空结果、部分结果、澄清、失败或已确认取消不收成功账单。停止与完成并发时，先完成的有效结果仍可结算。详见[计费说明](billing.md#云端-agent)。

`/wx stop` 和任务页「停止」只登记停止意图，恢复运行器负责查询并请求上游停止。新建、切换会话保留旧任务执行，离开原会话后可去任务页查结果；重置、归档、清空、删除、停用插件或解绑微信会请求停止相关任务并作废自动投递资格。

`CLOUD_AGENT_ENABLED` 是新任务提交开关，关闭后按任务进度处理：

- 确定尚未提交的任务会结束为 `rejected`，不扣 credits，并释放预占次数。
- 已尝试提交、但尚未确认上游任务号的任务会保留停止意图，只读对账找到原任务后请求停止，不重新提交。
- 已关联上游任务号的任务继续查询、执行和结算，不会仅因关闭开关而自动取消。若要停止，用户可在任务页对本人任务点击「停止」，或在原会话发送 `/wx stop`；运营方需停下运行中任务时，还须在 AGT 侧检查并请求取消。

请求停止后，仍需等待上游权威终态；先完成的有效结果仍可计费，开关不能作为立即停止成本的保证。恢复期间保留有效的 `AGT_ORIGIN`、应用、tenant、`AGT_APP_KEY`、旧 profile 与回调密钥；删除凭据会阻断查询和停止。Plus 到期会为活动任务登记停止意图，与关闭新提交开关的行为不同；两种情况下，用户仍能查看本人保留的任务并请求停止。

微信上下文失效会暂存待发结果，不重新执行任务或重复扣费。页面提示等待接收时，可让用户向原微信发送 `/wx status` 恢复投递；普通文字可能另建任务。

## 数据保留与上线验收

清空或删除会话会清除相关任务在微伴保存的输入、结果、冻结请求与结果快照，隐藏任务并清理待发正文；账单与已结算金额保留。重置或新建会话不会删除云端记忆。当前不自动同步删除 AGT 的历史、记忆或微信副本，运营方应明确远端保留策略并处理用户数据请求。

本地测试不等于真实 AGT 与微信联调。对外开放前，使用运营方测试账号验证：

1. Plus 且无自备模型时，添加云插件、扫码，按实际快捷名发送 `/use 快捷名` 后提交文字任务，在任务页看到终态与微信回复；新建会话不产生任务或费用。
2. 重复消息不重复执行或结算；输入超限、余额不足和每日次数用尽有明确提示；失败和确认取消不收成功账单。
3. 请求停止、切换/删除会话、上下文失效恢复，以及服务重启后，任务仍按保存状态恢复，旧结果不串入新会话。
4. Free、云服务关闭或配置缺失时不允许新建任务；历史查询与请求停止仍可用，不向客户端暴露上游身份和凭据。
5. 关闭新提交开关后，分别验证未提交任务释放预占、提交待确认任务对账停止、已关联任务继续恢复；对后者显式请求停止并等待终态，核对执行次数与最终账单。

微伴不会替部署者自动开放生产开关。实际受理、回调、费用和数据保留应以当前部署配置及真实联调结果为准。
